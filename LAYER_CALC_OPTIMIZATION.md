# Оптимизация расчёта по слоям

## Проблема
Функция `calculate_per_layer()` выполняла расчёт для **всех слоёв сразу**, даже когда требовалось обновить только один слой. Это приводило к избыточным вычислениям и замедлению работы (до 13+ секунд при множестве слоёв).

## Решение
Добавлен новый метод `calculate_single_layer(layer_name)`, который выполняет расчёт **только для указанного слоя**.

## Использование

### Расчёт одного слоя
```python
calculator = Calculator(data_loader)

# Расчёт только для конкретного слоя
calculator.calculate_single_layer("Слой_1")

# С прогресс-баром
calculator.calculate_single_layer("Слой_1", progress_callback=lambda done, total: print(f"{done}/{total}"))
```

### Расчёт всех слоёв (параллельно)
```python
# Старый метод остаётся для расчёта всех слоёв
calculator.calculate_per_layer(progress_callback=lambda done, total: print(f"{done}/{total}"))
```

## Преимущества

1. **Отсутствие пересчёта** - при загрузке/обновлении слоя рассчитывается только этот слой
2. **Быстрый отклик** - время расчёта пропорционально одному слою, а не всем
3. **Гибкость** - можно комбинировать: сначала рассчитать все слои, потом обновить отдельные
4. **Совместимость** - старый метод `calculate_per_layer()` продолжает работать

## Пример сценария использования

```python
# При загрузке файла с несколькими слоями
for layer_name in data_loader.per_layer_calib.keys():
    # Расчёт только текущего слоя
    calculator.calculate_single_layer(layer_name)
    # Обновление UI с результатами
    update_ui_for_layer(layer_name)

# Если нужно пересчитать все слои заново
calculator.calculate_per_layer(progress_callback=update_progress_bar)
```

## Логирование времени выполнения

Оба метода используют декоратор `@profile_time`, который логирует время выполнения:
```
2026-08-05 17:30:45,123 - INFO - calculate_single_layer выполнено за 150.45 мс
2026-08-05 17:30:46,789 - INFO - calculate_per_layer выполнено за 2340.12 мс
```

Это позволяет выявлять узкие места и оптимизировать дальнейшую работу.
